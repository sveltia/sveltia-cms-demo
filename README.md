# Sveltia CMS Demo

The source of [demo.sveltiacms.app](https://demo.sveltiacms.app/), a live demo of [Sveltia CMS](https://github.com/sveltia/sveltia-cms) that anyone can try without an account or a repository.

## How it works

- `index.html` loads the latest Sveltia CMS from unpkg, and `config.yml` configures it with the `test-repo` backend, which keeps files in the browser’s [origin private file system](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system) (OPFS). Nothing a visitor does leaves their browser.
- The `<link rel="cms-seed-url" href="/seed/manifest.json">` element in `index.html` tells the CMS where to find the sample content. On the first sign-in, every file listed in the manifest is copied from `seed/` to OPFS. See [Seeding Content](https://sveltiacms.app/en/docs/backends/test#seeding-content) in the docs.
- The visitor’s changes are kept across reloads. To start over, choose Settings › Advanced › Erase All Data.

The sample content shows off:

- **Posts**: a multilingual collection in English, Japanese and French (`multiple_folders` structure), with a relation to Authors, filters, groups, a draft, a [table view](https://sveltiacms.app/en/docs/collections/entries/views#table-view) with custom columns (`table_columns`) and [bulk editing](https://sveltiacms.app/en/docs/collections/entries/operations#bulk-editing-entries) (`bulk_edit`)
- **Authors**: YAML entries with a collection-level media folder, table columns and bulk editing
- **Pages**: a nested collection shown as a tree
- **Field Types**: a file collection with one entry per built-in field type, showing its main options
- **API Examples**: [JavaScript API](https://sveltiacms.app/en/docs/api) examples defined in `api.js`: editor components, a field type and a string transformation, event hooks, and a Demo Guide custom page
- **Site Settings**, **Navigation** and **Theme**: singletons in YAML (with `single_file` i18n), JSON and TOML
- **Downloads**: an asset collection

## Repository layout

```
index.html           Admin page
config.yml           CMS configuration
api.js               JavaScript API examples
logo.svg             Logo and favicon
404.html             Keeps Cloudflare Pages from serving index.html for missing files
seed/                Sample content, laid out like a site repository
scripts/build.js     Builds the site into dist/
scripts/manifest.js  Lists the files in seed/ for seed/manifest.json
scripts/serve.js     Local preview server
scripts/site.js      List of the files to deploy, shared by the build and the server
_headers             Cloudflare Pages cache headers
_redirects           Serves seed/static/ at the public paths, e.g. /images/
wrangler.toml        Cloudflare Pages project settings
```

The build copies the site files and `seed/` to `dist/`, and adds `seed/manifest.json` listing the sample content.

## Editing the sample content

Add, change or remove files in `seed/`. The manifest is generated by the build and the local preview server, so there’s nothing else to update.

Paths in `seed/` mirror the paths in `config.yml`; for example, `seed/content/posts/en/hello.md` becomes `content/posts/en/hello.md` in the visitor’s browser. Visitors who have already signed in keep their existing copy until they erase their data.

## Local preview

```sh
npm run dev
```

This serves the demo at `http://localhost:8080/`, with a manifest listing the files currently in `seed/`. To try another build of Sveltia CMS than the latest release, e.g. one served by `pnpm preview` in the CMS repository, set `CMS_URL`:

```sh
CMS_URL=http://localhost:4173/sveltia-cms.js npm run dev
```

The demo content is copied to the browser only on the first sign-in, so after changing `seed/`, choose Settings › Advanced › Erase All Data to see the changes.

## Deployment

The site is hosted on Cloudflare Pages:

- Build command: `npm run build`
- Build output directory: `dist` (set in `wrangler.toml`)
- Custom domain: `demo.sveltiacms.app`
